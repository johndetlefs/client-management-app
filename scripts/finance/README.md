# Financial records and delivery tools

`npm run dev` / `npm run dev:next` explicitly select emulators. `npm run dev:live -- --hostname 127.0.0.1 --port 3001` explicitly selects the existing LIVE Firebase configuration from ignored local environment files. Use separate origins for emulator and LIVE sign-in. Finances labels the data environment. Production rejects emulator mode; LIVE refuses any emulator host variables. Never copy demo users or create owner credentials in production.

Synthetic checks require `NODE_ENV=development`, project `demo-cma-finance` and explicit localhost Auth/Firestore emulator hosts. `seed-synthetic.ts --seed`, `verify-ledger.ts`, `verify-reports.ts`, `verify-tax.ts` and `verify-backfill.ts` only operate on that disposable project. The backfill check exercises interrupted setup, resume, repeat, later corrections, exact source/report/export ties and private-data denial.

`backfill-owner.ts` is an offline, explicitly authorized Admin migration, never an application endpoint. It uses existing server credentials, independently verifies the exact Auth owner, membership and current user/tenant profile, creates no credentials or access grants, and defaults to a read-only dry-run. Pass an absolute private0600 JSON plan and output outside the repository plus an exact `--live-project`. `--apply` additionally requires `--approved-plan` matching the private dry-run's hash. Do not use apply while a delivery hold is active.

The plan contains original CSVs, reviewed source-row decisions, definite dated receipt allocations, evidence-based transfer pairs, owner workpapers, one reserve pot, and unresolved notes. Private plan/output files, original statements and generated financial exports never belong in Git. The canonical authoritative expense schedule must retain its undated entries; they remain visible pending evidence instead of receiving invented deduction dates.

A source is visible only after its import marker commits. A partially completed owner migration blocks financial report/edit loading until resumed. Stable operation markers make exact replay idempotent and preserve later owner corrections. Per-operation financial audit records retain actor, source identity and before/after values. Receipt reversal, expense review and tax allocation correction use the normal app's evidenced controls. Never delete imported source identity or blindly replay an old before-image over later owner work.

A migration's successful execution does not prove source/report accuracy. Re-read every source identity/date/amount and reviewed classification, compare receipts/allocations and invoice payment projections, confirm the authoritative schedule and explicit unresolved items, compare period reports/exports in minor units, and prove the actual local and hosted owner journeys separately. No script lodges, registers, sends invoices or moves money.

Canonical import identity normalizes CRLF/LF while `rawSourceHashes` retain the SHA256 of each observed exact UTF8 file. A text-only plan that normalized line endings can use `--record-source-provenance` with its unchanged approved plan hash: the guarded tool reads each original private filename, checks its canonical content and every immutable live row, and appends an idempotent metadata-only audit. It changes no financial rows, payments, invoice values or owner workpapers.
